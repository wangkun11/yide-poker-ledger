# 以德服人 · 微信客户端本地版

使用微信开发者工具导入本目录。发布自己的版本时，将 project.config.json 中的 AppID 和内置小程序码替换为自己的。

## 运行和发布

在微信开发者工具导入本目录并编译即可，无需云环境、服务器、AppSecret、登录接口或 npm 运行依赖。打开直接进入账本。正式运行目录为 `miniprogram/`，项目已移除 `cloudfunctionRoot`。

好友、草稿、历史、多选状态、餐费及垫付人使用 `wx.setStorageSync` 保存，每次修改立即落盘。保存失败回滚并弹出提示；读取失败或数据格式异常时阻止打开空账本覆盖原记录。

## 微信账号隔离与保留范围

使用微信 Storage 的用户与 AppID 隔离机制，同一手机切换微信账号时由微信客户端隔离缓存；代码不使用昵称、设备 ID 或自造账号模拟登录。固定存储键 `yide-ledger-local-v1` 仅在微信当前用户的存储空间中使用。

- 同一账号、同一设备重新打开可读取已保存账目；不跨设备同步。
- 换手机、清理小程序数据或重装微信可能丢失记录。本机存储不是永久云备份。
- 双账号隔离有模拟测试，发布前仍需在真机分别切换 A/B 微信账号验证平台隔离行为。
- 微信存储说明：https://developers.weixin.qq.com/miniprogram/dev/framework/ability/storage.html

## 小程序码

左上角展示用户提供的固定小程序码，原图打包在 `miniprogram/assets/miniprogram-code.jpg`，点击可放大。读取和展示均在本地完成，无云函数或网络图片依赖。支持微信右上角菜单分享小程序入口。

## 记账规则

- 默认每手 2000，盈亏 = 剩余筹码 − 手数 × 每手筹码，历史牌局平账后归档。
- 每局房费必填，无费用填 0；有房费需指定一位好友垫付。房费随该局保存，不影响筹码胜负。
- 汇总所选牌局，以累计筹码盈亏大于 0 判断水上好友，按各自累计盈利积分占所有水上好友盈利积分的比例，分别分摊房费和餐费。金额按最大余数法分配到分，确保费用合计不变。
- 汇总餐费也需指定垫付人，未选择时不展示最终金额。牌局盈亏单位为积分，10 积分 = 1 元；房费、餐费、返还与最终结算单位为元。最终结算 = 累计盈利积分 ÷ 10 − 分摊房餐费 + 房餐费垫付返还。积分换算不足一分钱时在收付两端分别分配尾差，保持总额平衡。
- 当前牌局每页 15 人；好友、历史和结算采用紧凑布局。最多 200 位好友、500 局历史、每局 50 人。

## 验证

```sh
npm test
npm run check
```

检查覆盖离线启动与存取、写入失败回滚、损坏数据保护、模拟微信用户存储隔离、房餐费计算。检查脚本禁止正式包出现云开发、网络请求、云登录及环境 ID。

真机验收：A 断网增加好友并保存牌局→重开确认；切换 B 看不到 A 的数据并记一笔→切回 A 只见 A 的记录；核对费用结算。关闭云环境不影响已安装本地版本的记账。

历史列表“修改”可编辑日期、每手积分、该局好友昵称、手数、剩余积分、房费和垫付人。修改在独立临时副本中进行，平账并保存成功后替换原牌局，保留原 ID 和勾选状态，不覆盖当前草稿；取消或保存失败保留原记录。历史昵称修改仅影响该局。已有费用数值按元解释，积分历史原值不变。
